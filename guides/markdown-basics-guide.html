Markdown Basics for Everyday Writing

Learn the Markdown syntax for headings, emphasis, lists, links, quotations, and code blocks, with examples you can adapt in notes and documentation.

OmniText Editorial Guide · Practical reference

Markdown is a lightweight way to add structure to plain text. Instead of selecting formatting controls, you type simple characters that describe headings, emphasis, lists, links, and code. The source remains readable as text, while a Markdown renderer can display it with formatting.

Headings create structure

Use a hash sign followed by a space to create a heading. One hash is typically the main page heading; two hashes create a section heading; three hashes create a subsection. Keep heading levels in a logical order so readers can understand the document outline.

Emphasis highlights key phrases

Surround a word or phrase with one asterisk for *italic* or two asterisks for **bold**. Use emphasis sparingly. If too much text is bold, the important points become harder to distinguish.

Lists organize related items

Use a hyphen and a space for an unordered list. Use a number followed by a period for an ordered list. Keep list items grammatically parallel where possible. If order matters, use a numbered list; if it does not, bullets are usually clearer.

Links connect useful resources

Write link text inside square brackets, followed by the destination in parentheses. For example: [OmniText](https://omnitext-online.vercel.app/). Use descriptive link text so readers know what will open. Avoid vague labels such as “click here” when a more meaningful description is available.

Blockquotes and code

Start a quoted paragraph with a greater-than sign and a space. For inline code, surround a short command or variable with backticks. For a multi-line code block, place three backticks on a separate line before and after the code. Code fences can include a language label to help some renderers apply syntax highlighting.

A small Markdown example

A useful note might begin with a heading, a short explanation, and a checklist or ordered steps. Preview the rendered result to catch missing spaces, unclosed code fences, or malformed links. The source and preview should communicate the same meaning.

Export and review

When a Markdown editor offers a download option, it typically saves the plain-text source with a .md extension. A Markdown file can be opened in a code editor or another compatible writing tool. Before sharing, test links, inspect heading hierarchy, and make sure code blocks are closed.

Key takeaway

Markdown renderers support slightly different extensions. If a document will be published in a specific platform, preview it in that platform before relying on advanced syntax.
